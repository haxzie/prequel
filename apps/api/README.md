# @prequel/api

Every Prequel API, as one Cloudflare Worker on `api.prequel.sh`.

Accounts and teams, the shared library and its uploads, the desktop sign-in
handshake, transcription, and the waitlist. The Next app in `apps/web` has no
route handlers at all — it is pages and nothing else.

## Why a Worker and not a Next route

Two reasons, and the second is the one that made it not a choice.

**D1 and R2 want bindings.** From Vercel, D1 is only reachable over Cloudflare's
REST API, which is an HTTPS round-trip on every query — paid on every dashboard
navigation, and again on every session check. A Worker gets both as bindings.

**Video does not fit through a serverless function.** Vercel's request body
limit is 4.5 MB and is infrastructure, not something application code can raise.
That limit is why `/api/transcribe` used to cap uploads at 4 MB when OpenAI
itself accepts 25 MB, and it rules out an export ever passing through.

Uploads do not pass through this Worker either. `POST /v1/videos` returns a
presigned PUT and the client talks to R2 directly — a Worker's own body limit is
100 MB, which a two-minute 4K export is comfortably past.

## Layout

```
src/index.ts        the Hono app: CORS, routes, the error floor
src/auth.ts         Better Auth — Google, magic links, teams, invitations
src/middleware.ts   resolves a session cookie *or* a device bearer token
src/db.ts           Drizzle over the D1 binding
src/env.ts          every binding, var and secret this Worker reads
src/lib/r2.ts       presigned upload and playback URLs
src/lib/ses.ts      transactional email
src/lib/ids.ts      row ids, share slugs, tokens, PKCE helpers
src/lib/rate-limit.ts  the transcription allowance, in D1
src/routes/         one file per domain
migrations/         generated by packages/db, applied by wrangler
```

The schema lives in `packages/db`, because `drizzle-kit` needs it and this
Worker needs it and they are the same definitions.

## Running it

```bash
cp .dev.vars.example .dev.vars      # then fill it in
pnpm --filter @prequel/db generate  # only after changing the schema
pnpm --filter @prequel/api migrate  # applies to the local D1
pnpm --filter @prequel/api dev      # :8787, everything simulated
pnpm --filter @prequel/api test
```

### Two dev modes, and when the local one is not enough

`pnpm dev` simulates D1 and R2 on disk. Fast, needs no Cloudflare account, and
right for almost everything — auth, teams, invitations, the library listing.

**It cannot finish a share.** A presigned URL is a signature over a real R2
endpoint, so an upload always lands in the live bucket, while `complete` HEADs
the local simulation, finds nothing, and answers "the upload didn't finish". The
object is sitting in R2 perfectly intact; the two halves are simply looking at
different buckets.

`"remote": true` on the R2 binding would fix that and is deliberately not set:
the tests read the same `wrangler.jsonc`, so it would point them at the live
bucket — a suite that writes to production storage and cannot run in CI without
a Cloudflare token.

To exercise the upload path end to end:

```bash
wrangler login
pnpm --filter @prequel/api dev:remote   # the whole Worker, on real bindings
```

That writes real objects and real rows. Deleting the video in the dashboard
removes both.

`.dev.vars` holds the secrets; the non-secret configuration is in
`wrangler.jsonc`. Both are listed in the root `.env.example`.

The web app needs `NEXT_PUBLIC_API_URL=http://localhost:8787` in `.env`, which is
what the checked-in example already sets.

## Two clients, one identity

The dashboard sends a session cookie. The desktop app cannot — that cookie is
scoped to `.prequel.sh`, which Electron never visits, and the renderer's CSP
(`connect-src 'self' prequel-media:`) forbids remote requests outright, so every
call comes from the main process. It holds an opaque device token instead.

`authenticate` in `src/middleware.ts` resolves either into the same
`{ userId, teamId }`, so no route handler knows which one it got.

### The sign-in handshake

The only channel between a browser and a native app on macOS is a URL, and a URL
is not private: `open` logs it, and another application can register the same
scheme and be handed it instead. So the link carries a code that is useless
alone.

```
app    → browser   /desktop/auth?challenge=base64url(sha256(verifier))&state=…
browser→ API       POST /v1/desktop/authorize   { challenge }        → { code }
browser→ app       prequel://auth?code=…&state=…
app    → API       POST /v1/desktop/token       { code, verifier }   → { token }
```

The verifier never leaves the app's memory until it is spent. The state is
checked against the sign-in that process started, so a link from anywhere else
is ignored. Codes are single-use and expire in five minutes, and every refusal
answers with the same message — telling "no such code" apart from "wrong
verifier" would confirm to somebody guessing that a code exists.

Tokens are stored as SHA-256. The plaintext exists in the response that created
it and in `auth.json` on the user's Mac, and nowhere else.

## Email, and why it will not send at first

SES refuses to send _from_ an address it has not verified, and while the account
is in the **sandbox** it refuses to send _to_ one either. Both failures reach the
app as a 500 on the sign-in form, so check the source rather than guessing:

```bash
node scripts/ses-status.mjs                      # sender, sandbox, identities
node scripts/ses-status.mjs add you@example.com  # start verifying one
```

A verified identity works as sender _and_ recipient, so verifying one address is
enough to send yourself a magic link and click it.

For production, verify the `prequel.sh` **domain** — DNS records rather than a
click — and request production access to lift the sandbox. `SES_FROM` in the
production env is `hello@prequel.sh` and will fail until that domain is verified;
sending Prequel's mail from some other domain would work but costs deliverability,
which is the slow version of the same failure.

## Deploying

```bash
wrangler d1 create prequel                     # once; put the id in wrangler.jsonc
wrangler r2 bucket create prequel-media        # once
wrangler secret put BETTER_AUTH_SECRET --env production
# …and the rest of the list in .env.example
pnpm --filter @prequel/api migrate:remote
pnpm --filter @prequel/api deploy
```

The bucket must stay **private**. Playback goes through a presigned GET with a
six-hour life, which is what makes a deleted recording actually stop playing.

Google's OAuth client needs `<API_URL>/api/auth/callback/google` as a redirect
URI, character for character — a trailing slash is a `redirect_uri_mismatch`.

## Things that will bite

**The cookie domain.** The dashboard and this Worker share one session because
both are inside `prequel.sh`. An API on any other registrable domain would never
be sent the cookie, and the dashboard would appear signed out the instant after
signing in. Locally the two are `localhost:3000` and `localhost:8787`; cookies
ignore the port, so that works with no domain set at all — which is why
`crossSubDomainCookies` is switched on by whether `APP_URL` is https.

**CORS cannot be `*`.** A browser refuses to send credentials to a wildcard
origin, so the origin is echoed from configuration.

**`nodejs_compat` is not optional.** Better Auth reaches for `node:crypto`, and
without the flag the Worker fails to start with an error that names nothing
useful.

**D1's `exec` splits on newlines.** A statement written across several lines
arrives truncated. Use `prepare().run()` for anything multi-line — the tests do.

**Migrations are generated into this app, not `packages/db`.**
`wrangler d1 migrations apply` resolves `migrations_dir` relative to
`wrangler.jsonc`, so `packages/db/drizzle.config.ts` writes here on purpose.
